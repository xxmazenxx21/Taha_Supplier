1. BUG FIX — Multer fileFilter type error (reported after initial delivery)
================================================================================

FILE: src/utils/multer/multer.ts

REPORTED ERROR (at FileInterceptor call sites, e.g. sub-category + product
controllers):
  Argument of type '{ limits...; fileFilter: (req, file, callback:
  FileFilterCallback) => void; storage... }' is not assignable to parameter of
  type 'MulterOptions'.
    Types of parameters 'callback' and 'callback' are incompatible.
      Type '(error: Error | null, acceptFile: boolean) => void' is not
      assignable to type 'FileFilterCallback'.
        Target signature provides too few arguments. Expected 2 or more, got 1.

ROOT CAUSE
  I had typed the filter callback as @types/multer's `FileFilterCallback`,
  which is an OVERLOADED interface:
      interface FileFilterCallback {
        (error: Error): void;              <-- 1-argument overload
        (error: null, acceptFile: boolean): void;
      }
  Nest's own MulterOptions (node_modules/@nestjs/platform-express/multer/
  interfaces/multer-options.interface.d.ts) declares a SINGLE concrete
  signature:
      callback: (error: Error | null, acceptFile: boolean) => void
  Nest's 2-arg function cannot satisfy the 1-arg overload, so the types are
  not interchangeable.

  Why my earlier `npx tsc --noEmit` missed it: this project's tsconfig.json
  sets `strictNullChecks` but NOT `strict`/`strictFunctionTypes`, so function
  parameters are compared bivariantly and the mismatch was tolerated. Your
  editor enforces the stricter check and was correct.

FIX
  a) Removed the `FileFilterCallback` import from 'multer'.
  b) Declared the callback type locally to match Nest exactly:
       type NestFileFilterCallback =
         (error: Error | null, acceptFile: boolean) => void;
  c) Typed the file param as a minimal structural shape satisfied by BOTH
     Nest's inline file type and Express.Multer.File:
       type FilterableFile = { originalname: string; mimetype: string };
  d) Restored the two-argument rejection call: callback(err, false).
  e) Derived Nest's options type WITHOUT importing Nest internals, and
     annotated both factories with it so TypeScript now validates fileFilter
     against Nest's contract AT THE DEFINITION, not at each call site:
       type NestMulterOptions =
         NonNullable<Parameters<typeof FileInterceptor>[1]>;
       export function multerOptions(f: UploadFolder): NestMulterOptions
       export function privateMulterOptions(f: PrivateUploadFolder): NestMulterOptions

  This means any future drift in Nest's Multer contract fails in one file
  instead of in every controller.

VERIFIED: passes `tsc --noEmit` AND `tsc --noEmit --strictFunctionTypes`;
          multer.ts has 0 lint errors (it had 5-6 at baseline).
