# Flutter Banner API Documentation

## Base URL

Use the application base URL, for example:

```text
http://localhost:3000
```

## Authentication

Banner read endpoints require a valid client token:

```http
Authorization: Bearer <CLIENT_TOKEN>
```

The backend currently protects these endpoints with the `CLIENT` role.

## Response format

All successful responses use:

```json
{
  "message": "Success",
  "data": {}
}
```

## Get banners

```http
GET /banner
Authorization: Bearer <CLIENT_TOKEN>
```

This endpoint returns all banners, including inactive banners. If the Flutter
screen should show only currently enabled banners, filter the response with:

```dart
final activeBanners = banners.where((banner) => banner.isActive).toList();
```

The backend orders banners by `sort_order ASC`, then `created_at DESC`.
Images are ordered by `sort_order ASC`.

## Get one banner

```http
GET /banner/{bannerId}
Authorization: Bearer <CLIENT_TOKEN>
```

Example:

```http
GET /banner/1
```

If the banner does not exist, the backend returns 404.


The image URL is a backend public path. In Flutter, prepend the API base URL
when the value is not already an absolute URL:

```dart
String imageUrl(String value) {
  if (value.startsWith('http://') || value.startsWith('https://')) {
    return value;
  }
  return '$baseUrl$value';
}
```

## Click action handling

Use the `click_action_type` of the tapped image.

### NONE

Do nothing. `click_target_id` and `click_target_data` are null.

### CATEGORY

Open the category screen using `click_target_id` as the category ID.

```text
click_action_type = CATEGORY
click_target_id = 5
```

### PRODUCT

Open the product details screen using `click_target_id` as the product ID.

```text
click_action_type = PRODUCT
click_target_id = 123
```

### BRAND

Open the brand/product listing screen using `click_target_id` as the brand ID.

```text
click_action_type = BRAND
click_target_id = 10
```

### FILTER

Open the product listing screen and apply `click_target_data` as the existing
product query filters. Supported fields are:

```json
{
  "subcategory_id": 2,
  "brand_id": 10,
  "search": "coffee",
  "available": 1,
  "offers": 1,
  "min_rating": 4,
  "sort": "price_asc",
  "page": 1,
  "per_page": 10
}
```

The current backend product sort implementation supports `bestSelling`,
`newest`, `topRated`, and `nameAsc`; use one of those values instead of
`price_asc` unless the backend is extended.

### PAGE

`PAGE` is not configured in the current backend. The backend rejects it with:

```text
PAGE action is UNKNOWN / VERIFY IN SOURCE
```

Do not depend on PAGE actions until a page identifier convention is added.

## Recommended Dart action model

```dart
enum BannerActionType { none, category, product, brand, filter, page }

class BannerImageModel {
  final int id;
  final String imageUrl;
  final int sortOrder;
  final String actionType;
  final int? targetId;
  final Map<String, dynamic>? targetData;

  BannerImageModel({
    required this.id,
    required this.imageUrl,
    required this.sortOrder,
    required this.actionType,
    this.targetId,
    this.targetData,
  });
}
```

On tap, switch on the server value, validate that the required target exists,
then navigate to the relevant Flutter screen. Never treat a server-provided
`image_url` as a Flutter route.

## Common errors

- 401: missing, expired, or invalid token.
- 403: token does not contain the CLIENT role.
- 404: requested banner does not exist.
