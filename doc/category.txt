FRONTEND DOCUMENTATION - ADMIN DASHBOARD CATEGORY MODULE

Base URL
- http://localhost:3000

Scope
This document covers only the admin-dashboard category controllers in the backend.
Relevant controller: src/category/category.controller.ts

Important note
The admin category endpoints are protected with the ADMIN role guard.
Use this header on every admin request:
Authorization: Bearer <admin_token>

If the token is missing, invalid, expired, or malformed, the backend returns:
- 401 Unauthorized

If the token exists but has no role, or the role is not ADMIN, the backend returns:
- 403 Forbidden

General validation rule
Global validation is enabled with whitelist and forbidNonWhitelisted.
Any unexpected field in the DTO is rejected with a 400 Bad Request.

GLOBAL RESPONSE FORMAT
The project uses a global response interceptor, so successful responses are wrapped like this:
{
  "message": "Success",
  "data": { ...actual payload... }
}

If the controller returns an object with its own message field, that message is used instead of "Success".

Important:
- Success responses are wrapped by the interceptor.
- Error responses still use Nest default format, such as { message, error, statusCode }.

COMMON FILE RULES
- File upload field name must be image
- Supported image types: image/jpeg, image/jpg, image/png, image/webp
- Maximum file size: 5MB
- Multipart form data is required when uploading an image

COMMON ERROR EXAMPLES
1) Missing token
Response:
{
  "message": "Unauthorized",
  "error": "Unauthorized",
  "statusCode": 401
}

2) No role in token
Response:
{
  "message": "You do not have permission (no role found)",
  "error": "Forbidden",
  "statusCode": 403
}

3) User role is not ADMIN
Response:
{
  "message": "You do not have the required roles to access this resource",
  "error": "Forbidden",
  "statusCode": 403
}

4) DTO validation error
Response:
{
  "message": [
    "name must be longer than or equal to 2 characters"
  ],
  "error": "Bad Request",
  "statusCode": 400
}

5) File validation error - too large
Response:
{
  "message": "Validation failed (current file size is 5242880, expected size is less than 5242880)",
  "error": "Bad Request",
  "statusCode": 400
}

6) File validation error - wrong mime type
Response:
{
  "message": "Validation failed (file buffer is not available; file type validation could not be performed; expected type is /^image\\/(jpeg|jpg|png|webp)$/)",
  "error": "Bad Request",
  "statusCode": 400
}

7) Wrong field name for file upload
Response:
{
  "message": "Unexpected field - logo",
  "error": "Bad Request",
  "statusCode": 400
}

8) Category not found on update
Response:
{
  "message": "Category not found",
  "error": "Not Found",
  "statusCode": 404
}

ADMIN ENDPOINTS

1) GET /category
Purpose: Get all categories for admin dashboard.
Access: ADMIN only
Method: GET

Headers:
Authorization: Bearer <admin_token>

Success response example:
{
  "message": "Success",
  "data": [
    {
      "id": 1,
      "name": "Electronics",
      "image": "http://localhost:3000/uploads/categories/abc123.png",
      "display_order": 1,
      "is_hidden": false,
      "created_at": "2026-09-18T10:00:00.000Z",
      "updated_at": "2026-09-18T10:00:00.000Z",
      "subcategories": [
        {
          "id": 11,
          "name": "Phones",
          "category_id": 1,
          "is_hidden": false
        }
      ]
    },
    {
      "id": 2,
      "name": "Home",
      "image": "http://localhost:3000/uploads/categories/xyz456.png",
      "display_order": 2,
      "is_hidden": true,
      "created_at": "2026-09-18T11:00:00.000Z",
      "updated_at": "2026-09-18T11:00:00.000Z",
      "subcategories": []
    }
  ]
}

Possible errors:
- 401 Unauthorized
- 403 Forbidden

Note:
This admin route is intended to return all categories, including hidden ones. The public route also uses GET /category but is not an admin-dashboard route.

2) POST /category
Purpose: Create a new category from the admin dashboard.
Access: ADMIN only
Method: POST
Content-Type: multipart/form-data

Request example (FormData):
name: "Electronics"
display_order: 1
is_hidden: false
image: <image file>

Headers:
Authorization: Bearer <admin_token>

Request DTO rules:
- name: string, required, min length 2
- display_order: optional integer, min 0
- is_hidden: optional boolean, accepted as true/false in multipart form
- image: optional file upload, if provided must be valid image

Success response example:
{
  "message": "Success",
  "data": {
    "id": 1,
    "name": "Electronics",
    "image": "http://localhost:3000/uploads/categories/abc123.png",
    "display_order": 1,
    "is_hidden": false,
    "created_at": "2026-09-18T10:00:00.000Z",
    "updated_at": "2026-09-18T10:00:00.000Z"
  }
}

Possible errors:
- 401 Unauthorized
- 403 Forbidden
- 400 Bad Request if name is too short
- 400 Bad Request if display_order is negative or not an integer
- 400 Bad Request if is_hidden is not a boolean value
- 400 Bad Request if no file is uploaded and the code expects one
- 400 Bad Request if image file exceeds 5MB
- 400 Bad Request if image mime type is invalid
- 400 Bad Request if file field name is not image

Example validation error:
{
  "message": [
    "name must be longer than or equal to 2 characters"
  ],
  "error": "Bad Request",
  "statusCode": 400
}

3) PATCH /category/:id
Purpose: Update a category.
Access: ADMIN only
Method: PATCH
Content-Type: multipart/form-data

Request example (FormData):
name: "Home Appliances"
display_order: 3
is_hidden: false
image: <new image file>

Headers:
Authorization: Bearer <admin_token>

Optional fields: name, display_order, is_hidden, image

Important behavior:
When a new image is uploaded, the previous image file is deleted from the server, but the database row is still updated normally.

Success response example:
{
  "message": "Success",
  "data": {
    "id": 1,
    "name": "Home Appliances",
    "image": "http://localhost:3000/uploads/categories/new-image.png",
    "display_order": 3,
    "is_hidden": false,
    "created_at": "2026-09-18T10:00:00.000Z",
    "updated_at": "2026-09-19T09:15:00.000Z"
  }
}

Possible errors:
- 401 Unauthorized
- 403 Forbidden
- 400 Bad Request if field values are invalid
- 400 Bad Request if image file is too large
- 400 Bad Request if image type is invalid
- 400 Bad Request if file field is not image
- 404 Not Found if category ID does not exist
- 500 Internal Server Error for invalid numeric ID or DB update issues

Example 404 response:
{
  "message": "Category not found",
  "error": "Not Found",
  "statusCode": 404
}

4) DELETE /category/:id
Purpose: Hide a category from the public list instead of deleting it permanently.
Access: ADMIN only
Method: DELETE

Headers:
Authorization: Bearer <admin_token>

Example request:
DELETE /category/1

Success response example:
{
  "message": "Success",
  "data": {
    "id": 1,
    "name": "Electronics",
    "image": "http://localhost:3000/uploads/categories/abc123.png",
    "display_order": 1,
    "is_hidden": true,
    "created_at": "2026-09-18T10:00:00.000Z",
    "updated_at": "2026-09-18T12:30:00.000Z"
  }
}

Important behavior:
This route does not delete the database row. It updates is_hidden to true.

Possible errors:
- 401 Unauthorized
- 403 Forbidden
- 500 Internal Server Error if the ID is invalid or Prisma update fails

Frontend usage checklist
- Always send Authorization header with a valid admin JWT.
- Use multipart/form-data for create and update when sending an image.
- Field name for the uploaded image must be image.
- For delete, pass only the category ID in the URL.
- Expect 400 for validation issues, 401 for authentication, 403 for authorization, and 404 for missing category on update.

Example: create category with admin token (curl)
curl -X POST http://localhost:3000/category \
  -H "Authorization: Bearer <admin_token>" \
  -F "name=Electronics" \
  -F "display_order=1" \
  -F "is_hidden=false" \
  -F "image=@/path/to/category.png"

Example: update category (curl)
curl -X PATCH http://localhost:3000/category/1 \
  -H "Authorization: Bearer <admin_token>" \
  -F "name=Home Appliances" \
  -F "display_order=2" \
  -F "is_hidden=false" \
  -F "image=@/path/to/new-category.png"

Example: delete category (curl)
curl -X DELETE http://localhost:3000/category/1 \
  -H "Authorization: Bearer <admin_token>"

Example: list categories for dashboard (curl)
curl -X GET http://localhost:3000/category \
  -H "Authorization: Bearer <admin_token>"

Summary
The admin dashboard category module is built around four main actions:
- GET /category -> list categories (admin view)
- POST /category -> create category
- PATCH /category/:id -> update category
- DELETE /category/:id -> hide category

All of them require ADMIN role and follow the same backend validation behavior for errors and uploads.
