AUTH API
Base URL: http://localhost:3000

This file contains only the implemented auth endpoints.

GENERAL RULES
- Public endpoints do not require a token.
- Token format: Authorization: Bearer <token>
- All non-public routes require a valid JWT.
- Invalid, missing, malformed, or expired token => 401 Unauthorized
- For admin-only routes, user.role must be ADMIN
- Missing role => 403 Forbidden
  { "message": "You do not have permission (no role found)", "error": "Forbidden", "statusCode": 403 }
- Wrong role => 403 Forbidden
  { "message": "You do not have the required roles to access this resource", "error": "Forbidden", "statusCode": 403 }

COMMON VALIDATION ERROR
- DTO validation failure => 400 Bad Request
- Example response:
  {
    "message": ["name must be longer than or equal to 2 characters"],
    "error": "Bad Request",
    "statusCode": 400
  }

1) POST /auth/signup
Public
Content-Type: application/json

Request body:
{
  name: string; required; min length 2
  shop_name?: string; optional; min length 2
  phone: string; required; regex ^\+?[1-9]\d{7,14}$
  email?: string; optional; valid email
  password: string; required; min length 8
  address?: string; optional
  latitude?: number; optional; Number conversion; max 7 decimals
  longitude?: number; optional; Number conversion; max 7 decimals
}

Success response:
{
  access_token: string,
  refresh_token: string,
  user: {
    id: number,
    name: string,
    email: string | null,
    phone: string,
    role: "CLIENT"
  }
}

Possible errors:
- 400 Bad Request for validation failure / extra field
- 409 Conflict if email already exists
  { "message": "Email already exists", "error": "Conflict", "statusCode": 409 }
- 409 Conflict if phone already exists
  { "message": "Phone number already exists", "error": "Conflict", "statusCode": 409 }
- 409 Conflict if Prisma unique constraint is triggered
  { "message": "<field> already exists", "error": "Conflict", "statusCode": 409 }

2) POST /auth/login
Public
Content-Type: application/json

Request body:
{
  email: string; required; valid email
  password: string; required; min length 8
}

Success response:
{
  access_token: string,
  user: {
    id: number,
    name: string,
    email: string,
    phone: string,
    role: string
  }
}

Possible errors:
- 400 Bad Request for validation failure
- 401 Unauthorized if email not found or password invalid
  { "message": "Invalid email or password", "error": "Unauthorized", "statusCode": 401 }

5) POST /auth/refresh
Public
Content-Type: application/json

Request body:
{
  refresh_token: string; required
}

The refresh token is rotated on every successful request. The old refresh token
becomes invalid and the response returns a new access_token and refresh_token.
Access tokens expire after 15 minutes. Refresh tokens expire after 30 days.

6) POST /auth/logout
Public
Content-Type: application/json

Request body:
{
  refresh_token: string; required
}

The supplied refresh token is revoked. The endpoint returns success even when
the token was already revoked. The client must clear both local tokens.

3) POST /auth/adminDashboard/signup
Public
Content-Type: application/json

Request body:
{
  name: string,
  email: string,
  password: string,
  phone: string
}

Notes:
- This route does not use a DTO class.
- It always creates an ADMIN user.
- Unknown fields are not rejected by the validation pipe here.

Success response:
{
  id: number,
  name: string,
  email: string,
  phone: string,
  role: "ADMIN"
}

Possible errors:
- 500 Internal Server Error if Prisma rejects the create or required data is invalid

4) POST /auth/adminDashboard/login
Public
Content-Type: application/json

Request body:
{
  email: string; required; valid email
  password: string; required; min length 8
}

Success response:
{
  access_token: string,
  user: {
    id: number,
    name: string,
    email: string,
    phone: string,
    role: "ADMIN"
  }
}

Possible errors:
- 400 Bad Request for validation failure
- 401 Unauthorized if email is missing, user is not ADMIN, or password is wrong
  { "message": "Invalid email or password", "error": "Unauthorized", "statusCode": 401 }
