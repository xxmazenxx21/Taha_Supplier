FRONTEND DOCUMENTATION - ADMIN DASHBOARD SUBCATEGORY MODULE

Base URL
- http://localhost:3000

Scope
This document covers the admin-dashboard subcategory endpoints in the backend.
Relevant controller: src/sub-category/sub-category.controller.ts

Important note
The admin subcategory endpoints are protected with the ADMIN role guard.
Use this header on every admin request:
Authorization: Bearer <admin_token>

If the token is missing, invalid, expired, or malformed, the backend returns:
- 401 Unauthorized

If the token exists but has no role, or the role is not ADMIN, the backend returns:
- 403 Forbidden

General validation rule
Global validation is enabled with whitelist and forbidNonWhitelisted.
Any unexpected field in the DTO is rejected with a 400 Bad Request.

GLOBAL RESPONSE FORMAT
The project uses a global response interceptor, so successful responses are wrapped like this:
{
  "message": "Success",
  "data": { ...actual payload... }
}

If the controller returns an object with its own message field, that message is used instead of "Success".

Important:
- Success responses are wrapped by the interceptor.
- Error responses still use Nest default format, such as { message, error, statusCode }.

COMMON FILE RULES
- File upload field name must be image
- Supported image types: image/jpeg, image/jpg, image/png, image/webp
- Maximum file size: 5MB
- Multipart form data is required when uploading an image

COMMON ERROR EXAMPLES
1) Missing token
Response:
{
  "message": "Unauthorized",
  "error": "Unauthorized",
  "statusCode": 401
}

2) No role in token
Response:
{
  "message": "You do not have permission (no role found)",
  "error": "Forbidden",
  "statusCode": 403
}

3) User role is not ADMIN
Response:
{
  "message": "You do not have the required roles to access this resource",
  "error": "Forbidden",
  "statusCode": 403
}

4) DTO validation error
Response:
{
  "message": [
    "name must be longer than or equal to 2 characters"
  ],
  "error": "Bad Request",
  "statusCode": 400
}

5) File validation error - too large
Response:
{
  "message": "Validation failed (current file size is 5242880, expected size is less than 5242880)",
  "error": "Bad Request",
  "statusCode": 400
}

6) File validation error - wrong mime type
Response:
{
  "message": "Validation failed (file buffer is not available; file type validation could not be performed; expected type is /^image\\/(jpeg|jpg|png|webp)$/)",
  "error": "Bad Request",
  "statusCode": 400
}

7) Wrong field name for file upload
Response:
{
  "message": "Unexpected field - logo",
  "error": "Bad Request",
  "statusCode": 400
}

8) Sub category not found on update
Response:
{
  "message": "Sub category not found",
  "error": "Not Found",
  "statusCode": 404
}

ADMIN ENDPOINTS

1) GET /sub-category
Purpose: Get all visible subcategories for the public frontend.
Access: public route
Method: GET

Success response example:
{
  "message": "Success",
  "data": [
    {
      "id": 11,
      "name": "Phones",
      "image": "http://localhost:3000/uploads/sub-category/abc123.png",
      "display_order": 1,
      "category_id": 1,
      "is_hidden": false,
      "created_at": "2026-09-18T10:00:00.000Z"
    }
  ]
}

Possible errors:
- 400 if validation issues exist in query params (not usually used here)
- 500 if database query fails

2) GET /sub-category/admin
Purpose: Get all subcategories for admin dashboard, including hidden ones.
Access: ADMIN only
Method: GET

Headers:
Authorization: Bearer <admin_token>

Success response example:
{
  "message": "Success",
  "data": [
    {
      "id": 11,
      "name": "Phones",
      "image": "http://localhost:3000/uploads/sub-category/abc123.png",
      "display_order": 1,
      "category_id": 1,
      "is_hidden": false,
      "created_at": "2026-09-18T10:00:00.000Z"
    },
    {
      "id": 12,
      "name": "Laptops",
      "image": "http://localhost:3000/uploads/sub-category/def456.png",
      "display_order": 2,
      "category_id": 1,
      "is_hidden": true,
      "created_at": "2026-09-18T11:00:00.000Z"
    }
  ]
}

Possible errors:
- 401 Unauthorized
- 403 Forbidden

3) POST /sub-category
Purpose: Create a new subcategory.
Access: ADMIN only
Method: POST
Content-Type: multipart/form-data

Request example (FormData):
name: "Phones"
category_id: 1
display_order: 1
is_hidden: false
image: <image file>

Headers:
Authorization: Bearer <admin_token>

Request DTO rules:
- name: string, required, min length 2
- category_id: integer, required, min 1
- display_order: optional integer, min 0
- is_hidden: optional boolean, accepted as true/false in multipart form
- image: optional file upload, if provided must be valid image

Success response example:
{
  "message": "Success",
  "data": {
    "id": 11,
    "name": "Phones",
    "image": "http://localhost:3000/uploads/sub-category/abc123.png",
    "display_order": 1,
    "category_id": 1,
    "is_hidden": false,
    "created_at": "2026-09-18T10:00:00.000Z"
  }
}

Possible errors:
- 401 Unauthorized
- 403 Forbidden
- 400 Bad Request if name is too short
- 400 Bad Request if category_id is invalid or missing
- 400 Bad Request if display_order is negative or not an integer
- 400 Bad Request if is_hidden is not a boolean value
- 400 Bad Request if uploaded file exceeds 5MB
- 400 Bad Request if image mime type is invalid
- 400 Bad Request if file field name is not image

4) PATCH /sub-category/:id
Purpose: Update an existing subcategory.
Access: ADMIN only
Method: PATCH
Content-Type: multipart/form-data

Request example (FormData):
name: "Smart Phones"
category_id: 1
display_order: 2
is_hidden: false
image: <new image file>

Headers:
Authorization: Bearer <admin_token>

Optional fields: name, category_id, display_order, is_hidden, image

Important behavior:
When a new image is uploaded, the previous image file is deleted from the server, but the database row is still updated normally.

Success response example:
{
  "message": "Success",
  "data": {
    "id": 11,
    "name": "Smart Phones",
    "image": "http://localhost:3000/uploads/sub-category/new-image.png",
    "display_order": 2,
    "category_id": 1,
    "is_hidden": false,
    "created_at": "2026-09-18T10:00:00.000Z",
    "updated_at": "2026-09-19T09:15:00.000Z"
  }
}

Possible errors:
- 401 Unauthorized
- 403 Forbidden
- 400 Bad Request if field values are invalid
- 400 Bad Request if image file is too large
- 400 Bad Request if image type is invalid
- 400 Bad Request if file field is not image
- 404 Not Found if subcategory ID does not exist
- 500 Internal Server Error if DB update fails

Example 404 response:
{
  "message": "Sub category not found",
  "error": "Not Found",
  "statusCode": 404
}

5) DELETE /sub-category/:id
Purpose: Hide a subcategory from the public list instead of deleting it permanently.
Access: ADMIN only
Method: DELETE

Headers:
Authorization: Bearer <admin_token>

Example request:
DELETE /sub-category/11

Success response example:
{
  "message": "Success",
  "data": {
    "id": 11,
    "name": "Phones",
    "image": "http://localhost:3000/uploads/sub-category/abc123.png",
    "display_order": 1,
    "category_id": 1,
    "is_hidden": true,
    "created_at": "2026-09-18T10:00:00.000Z",
    "updated_at": "2026-09-18T12:30:00.000Z"
  }
}

Important behavior:
This route does not delete the database row. It updates is_hidden to true.

Possible errors:
- 401 Unauthorized
- 403 Forbidden
- 500 Internal Server Error if the ID is invalid or Prisma update fails

Frontend usage checklist
- Always send Authorization header with a valid admin JWT.
- Use multipart/form-data for create and update when sending an image.
- Field name for the uploaded image must be image.
- For delete, pass only the subcategory ID in the URL.
- Expect 400 for validation issues, 401 for authentication, 403 for authorization, and 404 for missing subcategory on update.

Example: create subcategory with admin token (curl)
curl -X POST http://localhost:3000/sub-category \
  -H "Authorization: Bearer <admin_token>" \
  -F "name=Phones" \
  -F "category_id=1" \
  -F "display_order=1" \
  -F "is_hidden=false" \
  -F "image=@/path/to/subcategory.png"

Example: update subcategory (curl)
curl -X PATCH http://localhost:3000/sub-category/11 \
  -H "Authorization: Bearer <admin_token>" \
  -F "name=Smart Phones" \
  -F "display_order=2" \
  -F "is_hidden=false" \
  -F "image=@/path/to/new-subcategory.png"

Example: delete subcategory (curl)
curl -X DELETE http://localhost:3000/sub-category/11 \
  -H "Authorization: Bearer <admin_token>"

Example: list admin subcategories (curl)
curl -X GET http://localhost:3000/sub-category/admin \
  -H "Authorization: Bearer <admin_token>"

Summary
The admin dashboard subcategory module is built around five main actions:
- GET /sub-category -> public visible list
- GET /sub-category/admin -> admin list including hidden items
- POST /sub-category -> create subcategory
- PATCH /sub-category/:id -> update subcategory and remove old image
- DELETE /sub-category/:id -> hide subcategory

All admin routes require ADMIN role and follow the same backend validation behavior for errors and uploads.
