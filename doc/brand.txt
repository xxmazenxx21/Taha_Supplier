FRONTEND DOCUMENTATION - BRAND MODULE

Base URL
- http://localhost:3000

Scope
This document covers all brand API routes in the backend, including both public and admin endpoints.
Relevant controller: src/brand/brand.controller.ts
Relevant service: src/brand/brand.service.ts

GLOBAL RESPONSE FORMAT
The project uses a global response interceptor for successful responses.
All success responses are wrapped like this:
{
  "message": "Success",
  "data": { ...actual payload... }
}

If the controller returns an object with its own message field, that message is used instead of "Success".

Important:
- Successful responses are wrapped by the interceptor.
- Error responses still use Nest default format, such as { message, error, statusCode }.

GENERAL AUTH RULES
- Public endpoints do not require a token.
- Admin-only endpoints require:
  Authorization: Bearer <token>
- If token is missing, malformed, expired, or invalid: 401 Unauthorized
- If role is missing: 403 Forbidden
  message: "You do not have permission (no role found)"
- If user role is not ADMIN: 403 Forbidden
  message: "You do not have the required roles to access this resource"

COMMON VALIDATION RULES
- ValidationPipe is enabled globally with transform: true, whitelist: true, forbidNonWhitelisted: true.
- Extra fields in DTO payloads are rejected with 400 Bad Request.
- File uploads use multipart/form-data.
- Brand logo field name must be logo.
- Accepted file types: image/jpeg, image/jpg, image/png, image/webp
- Max file size: 5MB

PUBLIC ENDPOINTS

1) GET /brand
Purpose: Get all non-deleted brands for the frontend catalog.
Access: Public
Method: GET

Success response example:
{
  "message": "Success",
  "data": [
    {
      "id": 1,
      "name": "Nike",
      "logo": "http://localhost:3000/uploads/brands/nike-logo.png",
      "created_at": "2026-09-18T10:00:00.000Z",
      "updated_at": "2026-09-18T10:30:00.000Z",
      "brandSubCategories": [
        {
          "subCategory": {
            "id": 5,
            "name": "Running"
          }
        }
      ]
    }
  ]
}

Possible errors:
- 500 Internal Server Error if database query fails

2) GET /brand/:id
Purpose: Get one brand by ID.
Access: Public
Method: GET

Success response example:
{
  "message": "Success",
  "data": {
    "id": 1,
    "name": "Nike",
    "logo": "http://localhost:3000/uploads/brands/nike-logo.png",
    "created_at": "2026-09-18T10:00:00.000Z",
    "updated_at": "2026-09-18T10:30:00.000Z",
    "brandSubCategories": [
      {
        "subCategory": {
          "id": 5,
          "name": "Running"
        }
      }
    ]
  }
}

Possible errors:
- 404 Not Found if the brand does not exist or is soft deleted
  {
    "message": "Brand not found",
    "error": "Not Found",
    "statusCode": 404
  }

ADMIN ENDPOINTS

3) GET /brand
Purpose: Get brands for the admin dashboard, without the full relationship payload.
Access: ADMIN only
Method: GET

Note:
This route is defined in the controller as another GET /brand route with the admin guard. In practice, it is intended for admin dashboard use and requires an admin token.

Success response example:
{
  "message": "Success",
  "data": [
    {
      "id": 1,
      "name": "Nike",
      "logo": "http://localhost:3000/uploads/brands/nike-logo.png",
      "created_at": "2026-09-18T10:00:00.000Z",
      "updated_at": "2026-09-18T10:30:00.000Z"
    }
  ]
}

Possible errors:
- 401 Unauthorized
- 403 Forbidden

4) POST /brand
Purpose: Create a brand.
Access: ADMIN only
Method: POST
Content-Type: multipart/form-data

Request fields:
- name: string, required, min length 2
- subcategory_ids: optional array of numbers
- logo: required file, valid image type and size <= 5MB

Example request (FormData):
name: "Nike"
subcategory_ids: [5, 8]
logo: <image file>

Success response example:
{
  "message": "Success",
  "data": {
    "id": 1,
    "name": "Nike",
    "logo": "http://localhost:3000/uploads/brands/nike-logo.png",
    "created_at": "2026-09-18T10:00:00.000Z",
    "updated_at": "2026-09-18T10:00:00.000Z"
  }
}

Possible errors:
- 401 Unauthorized
- 403 Forbidden
- 400 Bad Request for validation issues or invalid logo file
- 409 Conflict if a brand with the same name already exists
- 404 Not Found if one or more subcategory_ids do not exist
  {
    "message": "Subcategories not found: 999",
    "error": "Not Found",
    "statusCode": 404
  }

5) PATCH /brand/:id
Purpose: Update brand details.
Access: ADMIN only
Method: PATCH
Content-Type: multipart/form-data

Allowed fields:
- name: optional string, min length 2
- subcategory_ids: optional array of numbers (accepted by DTO, but relationship changes are not managed here; use dedicated subcategory endpoints for relation updates)
- logo: optional file, valid image

Important behavior:
When a new logo is uploaded successfully, the previous logo on disk is deleted.
If the brand is missing, the newly uploaded file is also cleaned up before the 404 is thrown.

Success response example:
{
  "message": "Success",
  "data": {
    "id": 1,
    "name": "Nike updated",
    "logo": "http://localhost:3000/uploads/brands/new-logo.png",
    "created_at": "2026-09-18T10:00:00.000Z",
    "updated_at": "2026-09-19T09:15:00.000Z"
  }
}

Possible errors:
- 401 Unauthorized
- 403 Forbidden
- 400 Bad Request for validation issues or invalid logo file
- 404 Not Found if brand ID does not exist
- 409 Conflict if a duplicate brand name is found

6) DELETE /brand/:id
Purpose: Soft delete a brand.
Access: ADMIN only
Method: DELETE

This does not remove the row from the database. It sets deleted_at to the current time.

Success response example:
{
  "message": "Success",
  "data": {
    "id": 1,
    "name": "Nike",
    "logo": "http://localhost:3000/uploads/brands/nike-logo.png",
    "deleted_at": "2026-09-18T12:00:00.000Z"
  }
}

Possible errors:
- 401 Unauthorized
- 403 Forbidden
- 404 Not Found if the brand is missing or already soft deleted

7) POST /brand/:id/subcategories
Purpose: Attach multiple subcategories to a brand.
Access: ADMIN only
Method: POST
Content-Type: application/json

Request body:
{
  "subcategory_ids": [5, 8, 10]
}

Validation rules:
- subcategory_ids is required
- array cannot be empty
- values must be integers and unique

Success response example:
{
  "message": "Success",
  "data": {
    "id": 1,
    "name": "Nike",
    "logo": "http://localhost:3000/uploads/brands/nike-logo.png",
    "brandSubCategories": [
      {
        "id": 20,
        "brand_id": 1,
        "subcategory_id": 5,
        "subCategory": {
          "id": 5,
          "name": "Running"
        }
      }
    ]
  }
}

Possible errors:
- 401 Unauthorized
- 403 Forbidden
- 404 Not Found if brand does not exist
- 404 Not Found if one or more subcategory ids are missing
- 400 Bad Request if body is invalid

8) DELETE /brand/:id/subcategories/:subcategoryId
Purpose: Remove a specific subcategory relationship from a brand.
Access: ADMIN only
Method: DELETE

Success response example:
{
  "message": "Success",
  "data": {
    "deleted": true
  }
}

Possible errors:
- 401 Unauthorized
- 403 Forbidden
- 404 Not Found if the relation does not exist
- 404 Not Found if the brand itself does not exist

FRONTEND USAGE EXAMPLES

Create brand (curl)
curl -X POST http://localhost:3000/brand \
  -H "Authorization: Bearer <admin_token>" \
  -F "name=Nike" \
  -F "subcategory_ids=[5,8]" \
  -F "logo=@/path/to/logo.png"

Update brand (curl)
curl -X PATCH http://localhost:3000/brand/1 \
  -H "Authorization: Bearer <admin_token>" \
  -F "name=Nike Updated" \
  -F "logo=@/path/to/new-logo.png"

Delete brand (curl)
curl -X DELETE http://localhost:3000/brand/1 \
  -H "Authorization: Bearer <admin_token>"

Get all brands (curl)
curl -X GET http://localhost:3000/brand

Get one brand (curl)
curl -X GET http://localhost:3000/brand/1

Add subcategories to a brand (curl)
curl -X POST http://localhost:3000/brand/1/subcategories \
  -H "Authorization: Bearer <admin_token>" \
  -H "Content-Type: application/json" \
  -d '{"subcategory_ids":[5,8]}'

Remove subcategory assignment (curl)
curl -X DELETE http://localhost:3000/brand/1/subcategories/5 \
  -H "Authorization: Bearer <admin_token>"

Summary
The brand module exposes both public-facing catalog APIs and admin dashboard APIs.
Public routes:
- GET /brand
- GET /brand/:id

Admin routes:
- GET /brand (dashboard list)
- POST /brand
- PATCH /brand/:id
- DELETE /brand/:id
- POST /brand/:id/subcategories
- DELETE /brand/:id/subcategories/:subcategoryId

All admin routes require ADMIN role and use the same interceptor + validation patterns as the rest of the backend.
