FRONTEND API DOC
Base URL: http://localhost:3000

This document includes only the APIs that are actually implemented in the backend.
The following routes are intentionally excluded because they are not implemented:
- GET /category
- GET /category/:id
- GET /brand
- GET /brand/:id
- GET /

GENERAL RULES
- Public endpoints do not require a token.
- All other endpoints require:
  Authorization: Bearer <token>
- Admin-only endpoints require the JWT role to be ADMIN.
- If token is missing, malformed, expired, or invalid: 401 Unauthorized
- If role is missing: 403 Forbidden
  message: "You do not have permission (no role found)"
- If role is not ADMIN: 403 Forbidden
  message: "You do not have the required roles to access this resource"
- DTO validation errors return 400 Bad Request with a message array.
- Uploaded files use multipart/form-data.
- File validation is enforced with max size 5MB and allowed mime types:
  image/jpeg, image/jpg, image/png, image/webp
- File upload field name matters. For category uploads it must be image, for brand uploads it must be logo.

COMMON VALIDATION RULES
- ValidationPipe is enabled globally with transform: true, whitelist: true, forbidNonWhitelisted: true.
- Extra fields in DTO payloads are rejected.
- Validation response example:
  {
    "message": ["name must be longer than or equal to 2 characters"],
    "error": "Bad Request",
    "statusCode": 400
  }

COMMON FILE ERRORS
- Missing file:
  400 Bad Request
  { "message": "File is required", "error": "Bad Request", "statusCode": 400 }

- File larger than or equal to 5MB:
  400 Bad Request
  { "message": "Validation failed (current file size is 5242880, expected size is less than 5242880)", "error": "Bad Request", "statusCode": 400 }

- Wrong file type / invalid mime:
  400 Bad Request
  { "message": "Validation failed (file buffer is not available; file type validation could not be performed; expected type is /^image\\/(jpeg|jpg|png|webp)$/)", "error": "Bad Request", "statusCode": 400 }

- Wrong multipart field name:
  400 Bad Request
  { "message": "Unexpected field - <field name>", "error": "Bad Request", "statusCode": 400 }

AUTH ENDPOINTS

1) POST /auth/signup
Public
Content-Type: application/json

Request DTO:
{
  name: string; required; min length 2
  shop_name?: string; optional; min length 2
  phone: string; required; must match ^\+?[1-9]\d{7,14}$
  email?: string; optional; valid email
  password: string; required; min length 8
  address?: string; optional
  latitude?: number; optional; converted with Number; max 7 decimal places
  longitude?: number; optional; converted with Number; max 7 decimal places
}

Success response:
{
  access_token: string,
  user: {
    id: number,
    name: string,
    email: string | null,
    phone: string,
    role: "CLIENT"
  }
}

Possible errors:
- 400 validation error if DTO fails or extra field is sent
- 409 Conflict if email already exists
  { "message": "Email already exists", "error": "Conflict", "statusCode": 409 }
- 409 Conflict if phone already exists
  { "message": "Phone number already exists", "error": "Conflict", "statusCode": 409 }
- 409 Conflict if a unique DB constraint is hit during create
  { "message": "<field> already exists", "error": "Conflict", "statusCode": 409 }

2) POST /auth/login
Public
Content-Type: application/json

Request DTO:
{
  email: string; required; valid email
  password: string; required; min length 8
}

Success response:
{
  access_token: string,
  user: {
    id: number,
    name: string,
    email: string,
    phone: string,
    role: string
  }
}

Possible errors:
- 400 validation error
- 401 Unauthorized if email does not exist or password is wrong
  { "message": "Invalid email or password", "error": "Unauthorized", "statusCode": 401 }

3) POST /auth/adminDashboard/signup
Public
Content-Type: application/json

Request body:
{
  name: string,
  email: string,
  password: string,
  phone: string
}

Notes:
- This route does not use a DTO class.
- It always creates an ADMIN user.
- Unknown fields are not rejected by the global validation pipe here.

Success response:
{
  id: number,
  name: string,
  email: string,
  phone: string,
  role: "ADMIN"
}

Possible errors:
- 500 Internal Server Error if Prisma rejects the create call or required data is invalid
- This route does not translate Prisma errors into a clean 400/409 response

4) POST /auth/adminDashboard/login
Public
Content-Type: application/json

Request DTO:
{
  email: string; required; valid email
  password: string; required; min length 8
}

Success response:
{
  access_token: string,
  user: {
    id: number,
    name: string,
    email: string,
    phone: string,
    role: "ADMIN"
  }
}

Possible errors:
- 400 validation error
- 401 Unauthorized if email does not exist, user is not ADMIN, or password is wrong
  { "message": "Invalid email or password", "error": "Unauthorized", "statusCode": 401 }

CATEGORY ENDPOINTS

5) POST /category
Admin only
Content-Type: multipart/form-data

Request DTO:
{
  name: string; required; min length 2
  display_order?: number; optional; integer; min 0
  is_hidden?: boolean; optional; accepts "true" / "false" from multipart form
}


Success response:
Created category object from Prisma, including:
- id
- name
- image
- display_order
- is_hidden
- created_at
- updated_at

Possible errors:
- 401 Unauthorized if token is missing/invalid
- 403 Forbidden if no role in token
- 403 Forbidden if user role is not ADMIN
- 400 Bad Request for DTO validation issues
- 400 Bad Request if image file is missing
- 400 Bad Request if uploaded file size is >= 5MB
- 400 Bad Request if uploaded file mime is wrong
- 400 Bad Request if file field name is not image

6) PATCH /category/:id
Admin only
Content-Type: multipart/form-data

Allowed optional fields:
{
  name?: string; min length 2
  display_order?: number; integer; min 0
  is_hidden?: boolean
}

Optional uploaded file:
- field name: image
- same validation rules as create

Success response:
Updated category object

Possible errors:
- 401 Unauthorized if token is missing/invalid
- 403 Forbidden if no role in token
- 403 Forbidden if user role is not ADMIN
- 400 Bad Request for DTO validation issues
- 400 Bad Request if image is provided but file size is >= 5MB
- 400 Bad Request if image mime is wrong
- 400 Bad Request if file field name is not image
- 404 Not Found if category id does not exist
  { "message": "Category not found", "error": "Not Found", "statusCode": 404 }
- 500 Internal Server Error if id is not numeric and Prisma rejects after unchecked +id conversion
- 500 Internal Server Error if old image deletion fails for any reason other than ENOENT

7) DELETE /category/:id
Admin only

This does not delete the category row. It hides it by setting is_hidden to true.

Success response:
Updated category object with is_hidden: true

Possible errors:
- 401 Unauthorized if token is missing/invalid
- 403 Forbidden if no role in token
- 403 Forbidden if user role is not ADMIN
- 500 Internal Server Error if id is invalid or does not exist, because Prisma update error is not translated to 404

BRAND ENDPOINTS

8) POST /brand
Admin only
Content-Type: multipart/form-data

Request DTO:
{
  name: string; required; min length 2
}


Success response:
Created brand object from Prisma, including:
- id
- name
- logo
- created_at
- updated_at
- deleted_at

Possible errors:
- 401 Unauthorized if token is missing/invalid
- 403 Forbidden if no role in token
- 403 Forbidden if user role is not ADMIN
- 400 Bad Request for DTO validation issues
- 400 Bad Request if logo file is missing
- 400 Bad Request if logo size is >= 5MB
- 400 Bad Request if logo mime is wrong
- 400 Bad Request if file field name is not logo
- 409 Conflict if brand name already exists
  { "message": "Brand with this name already exists", "error": "Conflict", "statusCode": 409 }
- 500 Internal Server Error if database save fails after file upload; server attempts to remove uploaded file before rethrowing

9) PATCH /brand/:id
Admin only
Content-Type: multipart/form-data

Allowed optional fields:
{
  name?: string; min length 2
}

Optional uploaded file:
- field name: logo
- same validation rules as create

Success response:
Updated brand object

Possible errors:
- 401 Unauthorized if token is missing/invalid
- 403 Forbidden if no role in token
- 403 Forbidden if user role is not ADMIN
- 400 Bad Request for DTO validation issues
- 400 Bad Request if logo size is >= 5MB
- 400 Bad Request if logo mime is wrong
- 400 Bad Request if file field name is not logo
- 404 Not Found if no active brand matches the id
  { "message": "Brand not found", "error": "Not Found", "statusCode": 404 }
- 409 Conflict if another brand already has the same name
  { "message": "Brand with this name already exists", "error": "Conflict", "statusCode": 409 }
- 500 Internal Server Error if id is invalid after unchecked +id conversion
- 500 Internal Server Error if deleting the old logo fails for a reason other than ENOENT

10) DELETE /brand/:id
Admin only

This is a soft delete. It sets deleted_at to the current date and does not delete the logo file.

Success response:
Updated brand object with deleted_at set

Possible errors:
- 401 Unauthorized if token is missing/invalid
- 403 Forbidden if no role in token
- 403 Forbidden if user role is not ADMIN
- 404 Not Found if no active brand matches the id
  { "message": "Brand not found", "error": "Not Found", "statusCode": 404 }
- 500 Internal Server Error if id is invalid after unchecked +id conversion

IMPORTANT NOTES FOR FRONTEND
- Do not call the GET routes for category/brand because they are stubbed and do not return real data.
- Use the public auth routes to sign in and create accounts.
- For admin actions, send the token in the Authorization header every request.
- Category/brand create and update requests are multipart/form-data, not JSON.
- For uploads, the frontend must send the exact field names: image for category and logo for brand.
- Brand names are unique. Category names are not unique in the current backend model.
